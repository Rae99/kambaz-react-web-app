Below is a compact, step-by-step explanation of the four things you asked about:

Syntax you see	What it really is	Why we write it that way
todosSlice.actions	an object that Redux Toolkit created. It contains one action-creator function for every reducer you listed (addTodo, deleteTodo, updateTodo, setTodo).	
export const { addTodo, deleteTodo, … } = todosSlice.actions;	ES6 object-destructuring. We pull those four action-creator functions out of todosSlice.actions and export them one-by-one so components can say dispatch(addTodo(...)).	
todosSlice.reducer	one single reducer function generated by RTK. It knows how to handle all four action types.	
export default todosSlice.reducer;	We export that reducer as the default so the store can import it: configureStore({ reducer: { todos: todosReducer } }).	


⸻

What exactly is “action” vs. “action creator”?

Term	Plain definition	In your slice
Action creator	A function that you call in code (addTodo({...})). It returns an action object.	addTodo, deleteTodo, … (those you exported).
Action (object)	A plain JS object that Redux dispatches. Shape Always = { type: "sliceName/reducerName", payload?: any }.	Example produced by addTodo({ title:"Run" }):{ type: "todos/addTodo", payload: { title:"Run" } }


⸻

What is payload and why does it “look like a todo”?
	•	Whatever argument you pass into the action creator becomes action.payload.
	•	addTodo ⇒ you pass a draft todo ({ title: "Run" }) → that is the payload.
	•	deleteTodo ⇒ you pass an id ("2") → that id becomes the payload.
	•	updateTodo ⇒ you pass a full todo object (with id) → payload is that object.

So “payload is a todo” only for the add / update cases; it can be anything you decide to send.

dispatch(addTodo({ title: "Jog" }))
//           └── payload for addTodo reducer

dispatch(deleteTodo("2"))
//                └── payload (just an id) for deleteTodo reducer

Inside each reducer you wrote, you read it with action.payload.

⸻

Why not mutate state directly?

RTK’s createSlice uses Immer under the hood, so lines like

state.todos = newTodos;           // looks mutative
state.todo  = { title: "" };

are actually converted to immutable updates for you—so the code stays short but safe.

Quick mental map

createSlice ─► slice
             │
             ├─ slice.actions      (object)  ─►  action creators
             └─ slice.reducer      (function) ─►  store reducer

Export both, use the creators in dispatch(...), put the reducer into configureStore.

Once this mental picture is clear, the dot-syntax (.actions, .reducer) feels natural.
